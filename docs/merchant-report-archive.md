# 营业记录归档与账单详情

店铺后台「营业记录」按完整结账账单显示，一次结账包含多项计时也只占一行。金额来自 `player_checkouts.total`，不是重新计算历史规则，也不是简单相加各计时费用。日期范围以店铺时区的零点转换为 UTC 查询，详情、收款及时间轴显示店铺时间。

默认显示未归档账单，可切换已归档或全部。点「账单详情」查看玩家与账单编号、开始/结束/结账时间、累计计时时长、计费小计、结账总额、现场收款方式及员工、已有的结账后余额、全部计时记录和收费调整明细，以及与玩家历史账单相同的完整时间轴。多项计时的累计时长可能包含重叠，不等于玩家停留时长。

店主和可写员工（manager）可以在桌面或手机列表里直接点「归档账单」／「恢复账单」，无需打开详情。列表不重复显示每行归档状态，由筛选和动作名称区分；点击时禁用按钮防止重复操作，失败在该行提示且允许重试。请求显式设置目标状态，同状态重试不会重复改变营业额，也不受扣款操作的待确认编号限制。详情内仍可操作并查看最后归档操作信息。只读员工只能查看。归档后该账单从默认列表和营业额汇总中排除，恢复后重新计入。切换列表筛选不会改变这个营业额口径；查看已归档列表时，营业额仍是当前日期范围内未归档账单的合计。消费笔数、资产发放和投币次数不受归档影响。旧的按计时流水接口同样隐藏已归档账单，玩家贡献报表的营业额同样排除归档金额。

归档不是退款、删除或重新结账：原始账单、玩家个人历史、收款记录、资产余额、收费历史和封顶历史不变。已归档账单仍有完整详情，仍参与后续计费的已支付封顶计算。旧账单没有保存时间轴时，沿用玩家历史查询的兼容重建，以持久化费用为依据，不按现行规则重新计价。

`0035_checkout_report_states.sql` 新建独立店铺范围的元数据表，初始为空，不更新原账单或余额；可以重复执行。按 `(shop_id, checkout_id)` 保留归档状态、最后操作时间和员工编号。重复提交相同状态不会覆盖操作人和时间。恢复也保留最后操作信息。员工编号来自实际认证身份，不采用客户端提交的编号。该表带结账外键，并沿用导出写锁保护，导出时不能修改归档状态。

业务 JSON 备份导出全部账单及归档元数据，跨库恢复后保持报表口径；仅配置备份不包含归档数据。引入归档前的 v2 业务备份缺少该表时视为空，其余缺失表仍报错。v1 格式保持原表集合。导出仍直接读取业务表，额度及进度机制不变。

相关 API：

- `GET /api/v1/shops/:shopCode/staff/reports/checkouts?from=<iso>&to=<iso>&archive=active|archived|all&limit=50&offset=0`：返回 `{ records, page: { limit, offset, hasMore } }`，日期范围按结账时间左闭右开，默认未归档。
- `GET /api/v1/shops/:shopCode/staff/reports/checkouts/:checkoutId`：返回 `{ record, receipt }`，`receipt` 复用玩家历史账单内容。
- `POST /api/v1/shops/:shopCode/staff/reports/checkouts/:checkoutId/archive`：输入 `{ archived: true|false }`，返回 `{ archived }`。跨店/不存在账单返回 404；只读员工和非员工返回 403；导出写锁返回 423。

新列表金额为元；存储仍为整数分，业务时间仍为 UTC。迁移由现有 `deploy:beta` 部署流程运行，不需要另外转换历史数据。
