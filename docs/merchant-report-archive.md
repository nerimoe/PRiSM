# 历史记录、经营分析与账单归档

店铺后台「历史」页（原「营业记录」`/reports` 自动跳转至 `/history`）合并了多维经营统计分析与结账明细列表，并由页面顶部统一的时间选择器（`近 7 天 / 近 14 天 / 近 30 天 / 上个月 / 自定义`）同步驱动：修改日期范围或切换预设后，上方的营收与客流趋势图、24 小时时段入场及在场分布、收款方式构成、热门资源活跃度（图表区间最长支持 366 天）以及下方的「结账记录」明细列表会同时联动更新。汇总指标统一展示在上方经营分析区，下方结账记录不再重复显示营业额、消费笔数、发放笔数和投币次数汇总行，也不再单独请求 `reports/summary`。每条账单来自 `player_checkouts.total`，一次结账包含多项计时也只占一行，不是重新计算历史规则，也不是简单相加各计时费用。日期范围以店铺时区的零点转换为 UTC 查询，详情、收款及时间轴显示店铺时间。

## 时间、时段分布与 Excel

预设只显示时间范围摘要，只有选中「自定义」才展开从／至日期输入框。「上个月」以门店当前日期为准，取上个自然月 1 日到最后一天，覆盖跨年、大小月和闰年二月。

时段入场分布按开始计时的门店本地小时统计；时段在场分布按实际计时区间与各小时的交集统计。两者均按「玩家 × 自然日 × 小时」去重，同一玩家多资源重叠计时不会重复计数，跨小时、跨夜会进入覆盖的各时段。区间结束采用右开边界，未结束计时截到数据返回的 `asOf`，不推算未来在场人数。在场表示有有效计时区间，不是门禁物理人数。

「导出 Excel」导出当前日期范围的统计概览、每日趋势、时段分布、收款方式、热门资源和结账记录，生成真正的 `.xlsx` 文件。结账记录遵循当前归档筛选并读取全部分页，不受当前页限制；金额单元格为数值（元），保留两位小数。导出失败显示错误且可重试，空数据仍生成列头。文件中标注统计时区、日期和归档口径；经营统计始终排除已归档账单。

历史页通过 `reports/analytics?source=1&startDate=...&endDate=...` 批量读取事实数据，前端计算周期指标、每日趋势、时段分布、收款构成和资源排名，并在浏览器生成 Excel。后端采用固定数量的区间查询（结账明细及累计时长、覆盖区间的计时、新玩家、设备操作、资产入账笔数），没有按天／小时循环查库，也不为导出另建后台计算任务。原汇总接口保留兼容仪表板和已有调用方。

默认显示未归档账单，可切换已归档或全部。点「账单详情」查看头部玩家名、仅在已归档时显示的「已归档」标签与收款方式胶囊、Bento 核心账单概览（计费小计、结账后余额、累计时长、结账时间）、内嵌卡片整理的入场/结束时间、现场收款员工、归档操作人与编号信息、全部计时记录与收费调整明细，以及与玩家历史账单相同的完整时间轴。多项计时的累计时长可能包含重叠，不等于玩家停留时长。

店主和可写员工（manager）可以在桌面或手机列表里直接点「归档账单」／「恢复账单」，无需打开详情。列表不重复显示每行归档状态，由筛选和动作名称区分；点击时禁用按钮防止重复操作，失败在该行提示且允许重试。请求显式设置目标状态，同状态重试不会重复改变营业额，也不受扣款操作的待确认编号限制。详情内仍可操作并查看最后归档操作信息。只读员工只能查看。归档后该账单从默认列表、营业额汇总以及「历史」经营分析（`reports/analytics`）的周期营收与收款方式统计中排除，恢复后重新计入。切换列表筛选不会改变这个营业额口径；查看已归档列表时，营业额仍是当前日期范围内未归档账单的合计。消费笔数、资产发放和投币次数不受归档影响。旧的按计时流水接口同样隐藏已归档账单，玩家贡献报表的营业额同样排除归档金额。

归档不是退款、删除或重新结账：原始账单、玩家个人历史、收款记录、资产余额、收费历史和封顶历史不变。已归档账单仍有完整详情，仍参与后续计费的已支付封顶计算。旧账单没有保存时间轴时，沿用玩家历史查询的兼容重建，以持久化费用为依据，不按现行规则重新计价。

`0035_checkout_report_states.sql` 新建独立店铺范围的元数据表，初始为空，不更新原账单或余额；可以重复执行。按 `(shop_id, checkout_id)` 保留归档状态、最后操作时间和员工编号。重复提交相同状态不会覆盖操作人和时间。恢复也保留最后操作信息。员工编号来自实际认证身份，不采用客户端提交的编号。该表带结账外键，并沿用导出写锁保护，导出时不能修改归档状态。

业务 JSON 备份导出全部账单及归档元数据，跨库恢复后保持报表口径；仅配置备份不包含归档数据。引入归档前的 v2 业务备份缺少该表时视为空，其余缺失表仍报错。v1 格式保持原表集合。导出仍直接读取业务表，额度及进度机制不变。

右侧「玩家资料」面板（「仪表板」「玩家」页）的「消费记录」标签页按日分组内嵌卡片列出这位玩家的全部结账单，不受日期范围限制，按结账时间倒序、每页 10 条。每行展示进店至离店起止时段、时长、折前小计与实付总额、收款方式与计费项数，已归档的变灰并标「已归档」（玩家确实付过钱，金额照常显示）。点一行打开与「历史」页「结账记录」相同的账单详情：Bento 概览、完整时间轴、计时与收费明细和归档操作。在面板里结账后列表随之刷新。

相关 API：

- `GET /api/v1/shops/:shopCode/staff/reports/checkouts?from=<iso>&to=<iso>&archive=active|archived|all&limit=50&offset=0`：返回 `{ records, page: { limit, offset, hasMore } }`，日期范围按结账时间左闭右开，默认未归档。
- `GET /api/v1/shops/:shopCode/staff/players/:playerId/checkouts?limit=50&offset=0`：一位玩家的全部结账单，含已归档，结构同上。
- `GET /api/v1/shops/:shopCode/staff/reports/checkouts/:checkoutId`：返回 `{ record, receipt }`，`receipt` 复用玩家历史账单内容。
- `POST /api/v1/shops/:shopCode/staff/reports/checkouts/:checkoutId/archive`：输入 `{ archived: true|false }`，返回 `{ archived }`。跨店/不存在账单返回 404；只读员工和非员工返回 403；导出写锁返回 423。

新列表金额为元；存储仍为整数分，业务时间仍为 UTC。迁移由现有 `deploy:beta` 部署流程运行，不需要另外转换历史数据。
