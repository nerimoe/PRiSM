# 店铺 JSON 数据备份与迁移

店主在「店铺设置 → 数据管理」下载或导入 JSON。默认导出业务备份，用于店铺备份及 beta／正式环境迁移；也可以只复制配置。两个环境都需要新版 Worker、既有 UTC 迁移和新增的 **0031_shop_data_transfer.sql**。0031 只新增传输暂存及账号关联表，不修改或删除已有业务数据。

## 备份范围

| 模式 | 包含的数据 |
| --- | --- |
| 业务备份 | 所有玩家（包括没有平台身份的纯前台玩家）、前台卡片档案、平台身份、余额与流水、兑换码与兑换记录、会话、历史账单及保存的时间轴、商品订单、前台收款、完整历史计费规则／发布版本／会话版本绑定；店铺员工资料、账号关联、设备操作记录、设备状态、连接记录及麻将座位 |
| 仅配置 | 计费效果、资产定义、计费方案、礼物和商品；生成新的计费发布版本，不包含玩家、财务历史及员工账号关联 |
| 两者共同包含 | 店铺名称、位置、半径与封面；所有店铺 `app_settings`、入场／收银／身份绑定设置；Bot/API Token 的验证记录；设备定义、别名及可跨密钥恢复的连接信息 |

v2 恢复来源店铺的资料及设置，保留目标店铺的编号、所属店铺 ID 和当前管理员。导入完成后后台刷新店铺资料、运营开关和设置。店铺时区继续跟随恢复后的位置。若在**同一数据库**复制店铺，设备 ID／公开链接与来源冲突时生成新编号，并更新座位、会话和设备操作中的对应引用；跨库无冲突时保留设备编号。

不复制平台全局的用户登录凭据、Passkey、OAuth 密钥、玩家个人卡片库、登录会话、设备扫码 Ticket、短期绑定码、请求去重与操作锁、实时活动推送 Token，也不复制全局封禁及登录审计。它们属于平台账号或短期运行状态，不属于店铺的业务备份。店铺范围中的禁用玩家、归档配置、已结账单和未结会话均包含在内。

纯前台玩家直接来自 `players` 与 `cashier_profiles`，不依赖平台身份或网页账号绑定。下载完成后界面展示来源环境、店铺、玩家／前台玩家／结账记录／设备数量；业务备份玩家数量为零时提示核对环境。beta 与正式版数据库各自独立，同名店铺也不能推断为同一个数据库或同一个店铺 ID。

## 账号和设备恢复

业务备份记录店铺账号与玩家／员工的关系，以及已验证登录身份的 `provider:subject`。导入不创建全局用户，也不安装登录密钥。账号访问店铺时按同一账号 ID 或已验证登录身份重新关联，平台绑定与原玩家必须一致；无法匹配的关系继续保存，并随下一次备份导出，可通过原外部平台身份重新绑定。跨库新建的纯 Passkey 账号没有可匹配的外部登录身份时，需要重新建立关联，不能凭昵称猜测。

设备连接字段在下载时使用来源环境密钥解密，导入暂存时使用目标环境密钥重新加密，所以不同 `URL_ENCRYPTION_KEY` 不会破坏连接。文件中的连接信息可包含明文密码和控制 Token；应当像保存数据库备份一样保管。Bot/API Token 的哈希验证记录保留，原 Token 值无法从哈希还原，接入时仍需持有原值并更新环境／店铺地址。

恢复过程不发送收款、赠送余额或硬件控制指令。历史设备命令保留；待执行命令改为已过期，设备在线状态恢复为离线，随后由实际设备重新报告状态，避免旧控制指令重复执行。

跨环境迁移前停止旧环境营业，处理在用设备与未结账单；核对新环境余额、规则、历史账单、账号绑定及设备连接后再营业，避免同一会话在两个环境继续计费。

## JSON 格式、时间与金额

```json
{
  "format": "prism-shop-data",
  "version": 2,
  "scope": "business",
  "exportedAt": "2026-10-06T00:00:00.000Z",
  "source": {
    "publicId": "source-shop",
    "name": "来源店铺",
    "timeZone": "Asia/Shanghai",
    "origin": "https://beta.example.com",
    "location": { "latitude": 31.23, "longitude": 121.47, "radiusMeters": 80 }
  },
  "storage": { "timeZone": "UTC", "money": "minor-units" },
  "settings": { "...": "计费设置摘要" },
  "shopProfile": {
    "name": "来源店铺", "latitude": 31.23, "longitude": 121.47,
    "radiusMeters": 80, "heroData": null
  },
  "tables": { "...": "完整的数据表数组，包括空表" }
}
```

上述是结构示意，不能直接导入。每行省略 `shop_id`，其余字段是数据库原始列和值；设备的三个加密连接字段使用可移植的 `hinata_url`、`hinata_password`、`ha_binding_json`。`account_links` 表包含账号关联资料。导入归属当前经鉴权的目标店铺，不接受文件指定任意店铺、表或列。

事件时间、UTC 规则、JSON 时间轴和金额保持存储原值。货币使用整数分；数量和百分比保持原值。历史计费版本与发布时区不再次转换。下载附件及分页中的 `payload_json`／`headerJson` 不进行展示时区转换。

新版 UI 同时支持 **v1 和 v2** 文件。v1 文件只能恢复其中已有的业务数据和设置摘要，并保留目标店铺资料，无法补回当时没有导出的设备或账号关联。

## 大文件与一致性

新版 UI 不再设置 10 MiB 文件上限或 128 KiB 单行上限。导出先在一个 D1 batch 中保存一致快照，再逐页下载；每个请求只读取一页，JSON 在浏览器组成。导入逐行读取文件，按约 256 KiB 或最多 1000 行上传分片；较大单行可以独占分片。分片请求必须小于 2 MiB，仍受 D1 单值／行大小、数据库容量及查询执行时间等服务限制。普通账单超过 128 KiB 可以导入，超过 D1 本身支持范围的记录会明确报错，不会截断。

浏览器下载最终 JSON Blob 仍需与文件大小相应的本地资源；不会把全部记录装进 Worker 内存。D1 需要足够空间存放临时快照／暂存数据。完成下载或导入后立即清理暂存记录；失败的任务可删除，遗留任务 24 小时过期并在下一次新建任务时清理。成功导入的结果凭据保留至任务过期，以支持网络失败后的幂等重试。

1. 选择空店铺和文件，逐行校验并上传。
2. 文件完整读取后提交所有表的数量和分片数量；缺表、截断、重复分片／标识、类型错误、外键失效、计费配置错误或目标已有数据均拒绝预检。
3. 预检将任务锁定，不能再追加或修改分片。界面展示来源与各类记录数。
4. 确认导入提交任务 ID、指纹和固定 `operationId`，无需再次发送整文件。
5. 后端再次校验目标状态，并在 D1 batch 第一条语句内断言目标及任务状态。所有业务数据、设置、去重结果与暂存清理在一个事务中完成；任一步失败全部回滚，可使用同一请求编号重试。

目标状态包含设置、账务设置及店铺资料；预检后修改位置、封面或配置，以及并发新增业务数据都会阻止导入。相同成功请求重试返回原结果，不重新导入，不再次变换时间或金额。

恢复业务历史时仅在同一事务内暂时停用自动生成计费版本／会话绑定的两个触发器，插入原记录后恢复。历史不可变约束、UTC 写入保护及部署维护围栏始终保留；失败回滚也恢复触发器。

## API

仅店主或已授权平台管理员访问；普通员工、其他店铺用户及 Bot Token 不可访问。新建任务及旧版接口每用户／店铺每分钟最多 10 次；同一任务的分页、上传及预检仍逐次鉴权，不受该 10 次限制。

- `POST /api/v1/shops/:shopCode/data/exports`：`{scope: "business" | "configuration"}`，创建快照，返回 `jobId`、原始 `headerJson`、表列表、记录数量和文件名。
- `GET .../data/exports/:jobId/page?after=0`：返回 `{rows:[{seq,table_name,payload_json}],cursor,done}`；使用返回的 `cursor` 请求下一页，直到 `done`。
- `DELETE .../data/exports/:jobId`：清理快照。
- `POST .../data/imports`：提交不含 `tables` 的原始文件头，创建上传任务。
- `POST .../data/imports/:jobId/parts`：`{table,part,rows}`；`part` 从 0 连续编号。同内容重试接受，不同内容占用同编号返回 409。
- `POST .../data/imports/:jobId/preview`：`{counts:{完整表名:行数},parts:分片数量}`，返回 `canImport`、指纹、错误、警告及计数。
- `POST .../data/imports/:jobId/apply`：`{fingerprint,operationId}`，原子恢复；已成功的相同请求直接重放结果。
- `DELETE .../data/imports/:jobId`：删除未完成的暂存任务，不能撤销已完成导入。
- `GET .../data/export?scope=business|configuration`：v2 原始 JSON 附件，适合常规直接下载；超大导出请使用分页任务，以避免单请求的 Worker 子请求预算。

旧版 `GET .../data/export?version=1`、`POST .../data/import/preview` 与 `POST .../data/import/apply` 保留兼容，仍有旧的 10 MiB／128 KiB 限制；新版后台不使用这些整文件接口。

验证覆盖纯前台注册／入场／收款后的备份、独立 D1 与不同密钥恢复、设备 ID 冲突和关联更新、超过 10 MiB 的文件与大于 128 KiB 的单行、分页快照一致性、账号关联、完整分片校验、幂等重试、失败回滚、权限和 v1 兼容。
