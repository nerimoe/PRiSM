# 删除测试账号

使用平台管理员账号进入 React「管理」页面（`/admin`），搜索 MuNET 用户，在对应账号行点击「删除账号」。确认框显示昵称、用户名、账号 ID 和清理范围；点击「确认删除账号」执行，取消不写入数据。普通玩家与店铺负责人没有这项平台权限。

删除的是 PRiSM 的网页登录账号，并不注销 MuNET 本身。下次用同一个 MuNET 身份登录时，会生成新的 PRiSM 用户 ID、重新同步 MuNET 卡片并进入首次注册／Passkey 设置流程。旧浏览器会话、Passkey 和 App Clip 授权码均失效。

## 清理范围

- 删除用户行、MuNET 登录关联、OAuth 凭据、全部登录会话、授权挑战、Passkey 和平台卡片。
- 删除店铺玩家账号关联、已验证的平台绑定、未使用的绑定码、网页员工账号关联、用户操作缓存以及 Live Activity 推送注册。
- 撤销该账号已领取的机台票据，避免清空认领人后票据被他人再次领取。
- 历史机台登录事件保留，账号和平台卡片引用设为空。

店铺、设备、店内玩家档案、Bot 平台身份、余额、会话和已结账账单保留。新账号可以重新绑定原店内玩家档案，继续使用其余额和账单。

删除店铺创建者时，`created_by` 改为现有的其他负责人；没有其他负责人时，由执行删除的管理员接管。删除某店唯一负责人时，管理员也会接管该店，即使其创建者是其他用户。已有其他负责人时，不给管理员添加新的店铺成员身份。所有账号清理和负责人调整在同一笔 D1 事务里执行，失败全部回滚。

当前登录账号不能删除。测试自己的账号时，先将另一个账号设为平台管理员，再登录另一个管理员账号执行删除。服务端在事务内重新验证执行人的权限与目标存在状态，避免并发请求使用已删除的管理员权限继续清理数据。

## API

`DELETE /api/v1/admin/users/:userId`，使用平台管理员 Cookie 会话，不需要请求体。

成功返回 `200 { "data": { "ok": true } }`。未登录 `401`，非平台管理员 `403`，目标不存在 `404`，删除当前登录账号返回 `409 CANNOT_DELETE_CURRENT_USER`。账号在操作期间已变化时返回 `409`，清理不部分提交。

无需数据库迁移。回归检查：`bun test packages/platform/test/admin-accounts.test.ts`，覆盖权限、凭据和票据撤销、重新注册、保留账单余额、负责人接管、事务回滚和并发管理员删除。
