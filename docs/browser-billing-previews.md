# Web 计费计算与只读输入

Web 的在店列表、玩家店铺账单、账号内账单、员工结账前预览、前台收款预览由浏览器 Web Worker 计算。线程复用 application 的结算服务、规则版本解析、优惠与封顶逻辑以及时间轴生成器。规则编辑器的 24 小时环图、玩家看到的当天入场规则在浏览器调用 core 的同一日历函数。没有另写一套收费公式。

营业记录列表读取已经结账并保存的总额，详情读取已保存的完整账单；这些历史记录不按当前规则重新计价。旧账单缺少保存的时间轴时，服务器仍用持久化收费项重建展示。营业额汇总仍由数据库聚合已保存金额。

统一平台新增只读接口：

- `GET /api/v1/shops/:shopCode/player/billing-inputs`：仅认证玩家本人的输入；不接受请求参数指定另一个玩家。资产定义只返回该玩家持有的类型和代码。
- `GET /api/v1/shops/:shopCode/staff/players/:playerId/billing-inputs`：店铺员工读取指定玩家，只读员工可查看；跨店或不存在玩家返回 404。
- `GET /api/v1/shops/:shopCode/cashier/profiles/:playerId/billing-inputs`：仅可写员工、已启用前台收银的店铺，且玩家必须是该店的前台档案。

独立 runtime 的前两个路径省略 `/shops/:shopCode`。返回 `{ playerId, billingSnapshot }`，输入结构与[在店列表](live-billing-performance.md)共用：包括未结会话、固定发布版本、当前封顶配置、资产及已支付历史。接口只读取数据，不生成预估，也不写入数据库。不增加数据库迁移。

每次打开或刷新预览都读取新输入，用服务器返回的 `capturedAt` 作为截止时刻；电脑的本地时间与时区不影响收费。时间点在输入里保持 UTC，浏览器还原 Date；最终展示仍按店家或玩家界面的时区策略。Worker 完成、失败、取消或超时后终止，离开相关页面、关闭玩家账单或员工详情也会取消预估；前台切换玩家会取消旧账单计算。

Web 获取店铺元数据时使用 `GET /api/v1/shops/:shopCode?pricing=raw`，可同时带 `date=YYYY-MM-DD`。该模式返回完整启用的入场方案和适用封顶方案，不在服务器生成每日分段或筛选当天规则；`pricingSchedule` 包含 `localDate`、`timeZone`、`clientCalculation: true`，`groups` 为空。浏览器依据规则中的 UTC 时钟、星期、日期和绝对时间范围计算当天在店铺时区可见的规则。不带此参数的旧接口保持原有计算后的响应。

预估只用于展示。普通结账确认不接受浏览器金额作为扣款依据；服务器重新读取规则版本、会话、余额及历史，核算并持久化结果。前台收款确认仍校验预估截止时间、会话集合与预计收款金额，篡改金额会拒绝收款。入场、停止计费等业务操作的校验也继续在服务器执行。

Swift、Bot、推送／Live Activity 和使用不可序列化自定义计费或优惠插件的运行时保留原有服务器预估。自定义运行时明确返回 `CLIENT_BILLING_UNAVAILABLE` 时 Web 才调用旧预览接口；网络失败、权限错误、资源超限或浏览器计算失败不会触发服务器预估回退。迁移本次覆盖 Web，不删除旧客户端依赖的 API。

回归验证包含：长时间未结会话、已修改和归档的固定规则版本、已支付封顶历史、优惠资产及每日限制、已停止未结账计时、前台无余额收款、跨店／玩家隔离、UTC 输入与店铺时区日历、Worker 生命周期及错误隔离。浏览器预览与后端权威预览逐字段对比；最终扣款和收款金额校验单独验证。

`check.yml` 的 browser 任务运行 `check-billing-previews-browser.cjs`，使用真实 Worker 检查前台和玩家账单金额、失败后重试、收款确认载荷、店铺与设备时区，以及不向后端请求 24 小时草稿预览。营业记录浏览器检查覆盖桌面／手机列表快捷归档、失败重试、营业额和只读权限。
