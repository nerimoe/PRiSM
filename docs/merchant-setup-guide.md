# 商户工作台的开店指引

店长第一次进入工作台，往往不清楚这套系统在店里怎么运转、钱从哪来、玩家会经历什么，也不知道要配哪些东西才能真正营业。「开店指引」页签从系统结构、玩家视角和店家日常三个维度讲清楚“正常营业是什么样”，按店铺经营方式列出接入步骤，并根据现有接口判断每一步是否已完成、标出需要留意的硬件或接入提示。

实现见 `packages/prism-web/src/ui/merchant/ShopGuide.tsx`（页面与加载）、`setup-guide.ts`（纯推导，测试在 `setup-guide.test.ts`）和 `BillingExplainer.tsx`（计费说明书）。

## 经营方式

不单独存字段，由现有设置推出（`operatingMode`）：

| 经营方式 | 判定 | 含义 |
| --- | --- | --- |
| 不使用计费（`devices`） | 没有任何资源组或资源设置计费方案 | 只用 PRiSM 的设备功能（开机、调空调、刷卡、投币、开门、麻将桌），收费在店家自己的其它经营平台完成 |
| 自助计费，无前台（`self`） | 有资源计费、未开前台收银 | 玩家在手机上入场计时、离店自助结账，从预存余额扣款；常见于无人值守、在线上群里运营的店。即使有店员，店员也不负责收钱 |
| 前台收银（`desk`） | 有资源计费、开启前台收银 | 有前台的店一定在前台收钱：玩家刷实体卡入场（按「前台资源」方案计时），离店时现场付款；带手机的玩家也可以自助 |

「有资源计费」由 `shopBills` 判断：任一资源组（含默认资源组）或资源专属方案已设置。这只是描述，不是开关——店铺没有整店计费开关。建店向导第一步就是三选一（「店里怎么收费？」）；「不使用计费」只是不创建方案，之后给哪个资源组或资源设置方案，哪里就开始计费。前台收银在「设置 → 营业与计费」切换，开启时须选定「前台资源」。选前台收银时，`POST /api/v1/merchant/shops` 的 `billingSetup.cashierEnabled: true` 会同时开启前台收银并创建名为「前台」的资源（`desk-<shopId>`）。

## 何时出现、默认落点

- 只对店长（owner）显示。
- 有未完成步骤时，「开店指引」排在页签最前，`/merchant/:shop` 默认跳到 `/merchant/:shop/guide`；全部完成后页签消失，默认进入「在店」，设置页标题右侧保留入口。
- 新建店铺的向导结束后直接进入指引。向导选择创建 Bot 凭据时，完成页直接展示两项配置（`接入凭据` 与 `API 地址`），凭据自己指明店铺，不再展示店铺编号。

## 页面结构

1. **PRiSM 接入支持与反馈（`PlatformSupport`）**：置顶展示 PRiSM 官方支持 QQ 群号（`1135111765`）与「复制群号」按钮，说明接入或使用 PRiSM 遇到问题与建议时可入群向平台团队咨询与反馈。
2. **经营方式**：当前方式及一句话说明，附「更改」链接（跳往「设置 → 营业与计费」）。
3. **这套系统怎么组织店铺（`StoreModel`）**：三栏核心概念卡：
   - **资源组决定怎么收费**：默认资源组和自定义资源组（如游戏区、休息区、麻将区）各自绑定计费方案，不设方案即免费；没有整店计费开关，单资源可设专属方案覆盖资源组。
   - **资源与 7 种能力**：资源是玩家扫码或碰 NFC 使用的对象（机台、空调、门锁、麻将桌或纯入场二维码），可按需挂载电源、空调、刷卡 · HINATA IO（默认直连、支持后台按键）、投币（独立能力）、开门密码或麻将桌能力。
   - **Bot、占用与事件**：店铺 Bot 也是资源（不供扫码），负责群内命令、绑定身份、同步昵称和按听众分组的播报组；刷卡、投币和麻将座位会自动记录占用，用来查在店位置与触发闲置自动关机。
4. **正常营业时，玩家这样用**：按经营方式画出玩家的一次到店。
   - 自助：碰 NFC 或扫码（支持 PRiSM Link App Clip 免安装与灵动岛实时看账单）→ 登录 →（要求绑定时）第一次来绑定身份（Bot 自动同步平台昵称）→ 确认计费规则（这台资源今天的计费规则与跨方案封顶进度；换区或换桌时说明要新增、保留或结束哪些计费）→ 用设备（开关机、调空调、刷卡及直连读卡器「+」直接加卡、投币及自动投币、开门、延迟关机、上麻将桌与原子换桌）→ 离店结账（App 灵动岛同步结束，店员/Bot 代结账同样同步）。
   - 前台：前台刷卡 → 店员点入场（按「前台资源」方案计时）→ 游玩（「在店」页按位置查人、实时看账单）→ 回前台付款；并说明带手机的玩家也可以自助。
   - 不计费：碰 NFC 或扫码 → 登录 →（门锁或麻将桌要求绑定时）绑定身份 → 操作设备（含空调、直连读卡器加卡、麻将桌），不计费。
5. **你每天在后台做什么**：按经营方式列出「在店」「玩家」「资源」「计费」「资产」「记录」「设置」等页签在日常里的真实用途（含按位置分组查人、Ctrl/Shift 批量结账、实时状态磁贴、自定义后台按键、归档测试账单等）。
6. **钱从哪来、怎么扣**（有资源计费时）：系统没有接入在线支付，余额只来自兑换码（批量生成与导出，在任何渠道售卖）、店员充值、礼物与活动；结账先抵扣优惠券，再扣赠送余额、最后扣充值余额，余额不够结不了账、计时继续，店员可「充值结账」或「改价结账」，也可由 Bot 将结账失败播报给店员。前台模式在最前面说明现场收款不进余额，系统只记录金额、收款方式和收银员。
7. **计费说明书**（有资源计费时）：打开图解弹窗（`BillingExplainer`），计费页标题旁也有同一入口，见下文。
8. **接入步骤**。
9. **按需配置**：Bot 播报组与命令回复、闲置自动关机、投币上限/自动投币与后台按键、资源组与分区计费、邀请店员（非前台，绑定平台身份即自动同步为 Bot 管理员）、新玩家礼物（拉新，不是付款方式）、优惠与活动、开启前台收银（自助店）或改用 PRiSM 计费（还没有资源计费时）、到店位置校验、数据备份与从 prism-neo 迁移。

## 接入步骤与完成判定

| 步骤 | 出现条件 | 完成条件 |
| --- | --- | --- |
| 设定收费标准 | 有资源计费 | 有有效余额资产（缺失时引导去「资产」恢复）；前台收银模式下还要求 `cashierResourceId` 指向一个已启用且实际有计费方案（专属或所属资源组）的非 Bot 资源（缺失或未设方案时 `deskProblem` 标红提示并引导去「设置 → 营业与计费」或「资源」）。哪些资源组计费在「资源」页设置，非前台场景资源组不设方案（免费）不算未完成 |
| 准备前台读卡器 | 前台收银 | 本浏览器已授权 HINATA 读卡器（WebHID `getDevices()` 中有 vendor `0xF822`）；浏览器不支持 WebHID 时提示用桌面版 Chrome 或 Edge |
| 给前台店员开账号 | 前台收银 | 店铺成员多于 1 人；说明在前台收款需要计费权限「管理」，且店员绑定平台身份后自动成为 Bot 管理员 |
| 确认玩家身份与 Bot | 有资源计费；或有门锁、麻将桌 | 不要求绑定；或至少一个已启用的 Bot 资源拥有有效凭据，且 `botOnline` 为真或 `botLastUsedAt` 非空。步骤内可直接改身份策略、预览绑定提示，并说明在「资源」页添加 Bot 后 Koishi 插件只需填 API 地址和接入凭据两项 |
| 准备玩家储值 | 自助计费 | 有可用兑换码（未用尽、未过期），或已有玩家余额大于 0 |
| 添加资源并配置能力 | 总是 | 至少一个非 Bot 店铺资源，且每个非 Bot 资源要么配置了至少一项能力，要么自身/所在启用资源组绑定了计费方案（`resourceBilled`；纯二维码入口与自动创建的「前台」资源若已绑计费方案即算配置完成，仅创建 Bot 资源不算完成此步）。步骤内同时展示不阻塞完成判定的配置提醒：直连 IO 仍在 E2EE、直连 IO 未签发设备令牌、投币能力未选按键、HA 连接只读账号未就绪，以及外部中继建议改直连提示 |
| 连接 TTLock 账号 | 有资源启用开门密码 | `ttLockConnection` 有 `clientId`、`clientSecret` 及 `accessToken` 或 `appAccount` |
| 贴好二维码或 NFC，自己试一次 | 总是 | 有资源计费且已有玩家档案；或店长勾选「我已试过」（`localStorage` 的 `prism.setup.trial.<shopCode>`） |

### 接口读取边界

`useSetupStatus` 在所有店主工作台页签挂载时复用同一份 8 个现有 GET 接口加载进度（`settings`、`merchant/machines`、`merchant/resource-groups`、`staff/settings`、`staff/players`、`merchant/shop-members`、`staff/presents`、`staff/redeem-codes`，`resource-groups` 失败时退回 `undefined` 以免误报 `unbilled`），不新增跨页请求，避免影响其它页面和浏览器检查脚本的接口约束。已创建 Bot 凭据但尚未接入时，每 15 秒自动复查一次，Bot 接入后自动更新；可选接口失败不阻塞工作台。

仅当真正打开「开店指引」页（`ShopGuide` 组件挂载）时，页面额外以 `.catch(() => null)` 读取两项只读诊断信息：
- `GET /api/v1/merchant/idle-power?shopId=`：判断「按需配置 → 闲置自动关机」是否已开启。
- `GET /api/v1/merchant/ha-connections?shopId=`：统计 `readAccess` 为 `needs_admin` 或 `failed` 的 Home Assistant 连接数，在「添加资源并配置能力」步骤内提醒启用只读账号以恢复实时状态。

## 玩家身份

`IdentityPolicyPicker.tsx` 在指引和「设置 → 玩家与身份」共用，两个选项，绑定在前：

- **要求绑定平台身份（推荐）**：玩家第一次进店前把绑定码发给店铺 Bot。店家因此知道每位玩家的 QQ 号等身份，Bot 也会自动同步玩家在聊天平台上的昵称；Bot 只在店铺群里响应时，只有群成员能进店。其下的高级勾选项「只允许已有档案的玩家绑定」（`autoRegister: false`）只用于迁移来的店，任何情况下都不作为默认值。
- **登录网页账号即可**：不需要 Bot，店家只知道玩家的 PRiSM 账号。

新店铺默认要求绑定并自动建档（含没有资源计费的店铺）。绑定提示、Bot 的命令权限、播报组与回复模板见 [integrations-and-machines.md](integrations-and-machines.md) 的 Integration 一节。

## 计费说明书（`BillingExplainer`）

`BillingExplainer` 用一个连贯的例子画四张图，数字与计费引擎一致（[billing-flow.md](billing-flow.md)），并附字段说明与配置注意事项：

1. **按单位计费、宽限内不进位**：每 30 分钟 10 元、宽限 5 分钟的阶梯图，35 分钟 10 元、36 分钟 20 元；开场宽限只在没操作设备时免单（开门、调空调与后台按键不算设备操作）。
2. **跨时段分别计算、时段封顶只管本时段**：日场 12 元/小时封顶 40、夜场 8 元/小时，14:00–20:30 共 64 元的累计曲线；并说明入场锁定规则版本。
3. **多条计费与消费封顶**：入场 64 元 + 麻将 30 元，全天消费封顶 80 元（消费封顶不再选适用规则，覆盖所有按时计费的规则）。
4. **结账扣款顺序**：94 → 消费封顶 −14 → 优惠券 −6 → 应付 74，先扣赠送余额 20、再扣充值余额 54。

字段说明除计费方式、基本信息、按时计费时段（含负数收费表示活动时段减免）、固定收费、消费封顶外，还说明了规则关系（「依赖」与「冲突」）；配置注意事项说明新建规则须成为资源组方案、资源专属方案、麻将对局方案或被其他规则「依赖」才会计费，并涵盖麻将「人满后一起开始」与「上桌立即开始」两种开局模式及直接换桌行为。末尾链接到计费页的计费模拟器（`/merchant/:shop/pricing?simulate=1` 直接展开），用本店规则试算。

## 资源入口：二维码与 NFC

二维码和 NFC 是同一个链接 `/t/:shop/:resource`。玩家打开后，设置了计费方案的资源先显示「计费规则」卡片（各方案今天的时段、跨方案封顶的进度和已计金额），确认后才开始计费；直连 HINATA IO 机台支持时，玩家还能在选卡区点「+」，把卡放到这台机器的读卡器上直接添加。NFC 标签写入 NDEF URI 记录即可；iPhone 碰一下唤起 hinata_go 里的 PRiSM Link App Clip（免安装，支持灵动岛实时更新账单），其它手机用浏览器或 HINATA Go 打开。资源二维码弹窗提供打印、复制链接，并写明 NFC 的写法。
