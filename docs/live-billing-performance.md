# 在店页计费预估与资源开销

统一平台的 `GET /api/v1/shops/:shop/staff/live-players` 默认只读取数据，不逐个生成结算预估或时间轴。商户页面先显示在店玩家、余额、入场时间和时长，再在 Web Worker 中逐个计算预估。选中的玩家优先计算，刷新或离开页面会终止旧线程，旧结果不能覆盖新列表。

响应由 `players` 与 `billingSnapshot` 组成：

```json
{
  "players": [{ "playerId": "player", "estimatedTotal": null, "sessions": [] }],
  "billingSnapshot": {
    "version": 1,
    "capturedAt": "2026-10-07T10:00:00.000Z",
    "assetDefinitions": [],
    "currentPricingConfigs": [],
    "pricingReleases": [],
    "players": [{
      "playerId": "player",
      "sessions": [],
      "holdings": [],
      "pastAppliedAdjustments": [],
      "pricingPaidHistory": {},
      "capPaidHistory": {}
    }]
  }
}
```

这是字段结构示意，实际玩家有完整未结会话。快照包含固定的计费发布版本、余额与优惠资产的有效期、已结账的封顶额度和优惠每日使用记录，不会因为当前方案已修改或归档而改变旧会话价格。设备操作只提供影响首段宽限期的布尔标记，不下发设备命令载荷与会话任意元数据。所有 SQL 按店铺隔离，公共配置只读取一次，所有发布版本及共享版本内容用两个批量查询读取；历史记录只分组一次，不按玩家反复扫描。15 名玩家使用 15 种不同发布版本的快照仍只需 9 条 SQL。

`billingSnapshot` 是引擎输入，不做店铺时区投影：时间点保持 UTC ISO 字符串；余额资产数量和已支付历史金额是整数分；计费配置的价格保持仓储返回的元单位。页面外层 `players` 仍遵守常规 API 店铺时区约定。浏览器将快照日期还原为 `Date`，以 `capturedAt` 为预估时刻，不采用操作员电脑的错误时钟。刷新重新获取完整快照。元数据和优惠效果的任意配置字符串不作为日期转换。

浏览器复用后端 `createSettlementService`、版本解析器、优惠资产逻辑与时间轴生成器，不维护第二套计费公式。读取快照后没有额外逐个玩家的 HTTP 预估请求。单个玩家计算失败只显示该玩家预估不可用，其他玩家继续计算；重试会重新读取快照。

预估只用于展示。Web 结账预览也在浏览器生成，停止计费和结账确认仍调用后端；后端读取数据库重新核算、校验余额并保存记录，不接收浏览器算出的应付作为扣费依据。前台玩家保持现场收款，不引入余额资产。

旧版／自定义运行时未提供快照读取能力，或使用不能序列化的额外计费／优惠插件时，保留后端预估响应。`?playerId=...` 是显式单玩家后端预估兼容入口，SQL 只读取该玩家的未结会话；新页面不调用此入口。

UTC 日历处理直接使用 `Date` 的 UTC 方法；其他地区时区最多缓存 32 份格式器配置，每次仍按事件日期解析偏移，保留夏令时。API 在单次响应内复用重复时间点的投影结果，缓存不跨响应保存。

迁移 `0034_device_commands_player_requested.sql` 只增加设备命令的店铺／玩家／时间覆盖索引，不修改或删除业务记录；可重复执行。查询设备操作宽限期时不再逐个玩家扫描整店命令历史。部署时仍需按既有流程运行 D1 迁移。

回归场景包含 15 名玩家持续 30 天未结账、未覆盖 24 小时的营业区间、封顶历史、修改并归档后的旧方案、已停止未结会话、优惠每日限制、设备操作宽限期、前台收款和跨店隔离。该固定样本每人 2790 元，浏览器与后端逐字段一致；新接口不执行服务器预估、不写入数据库，响应小于 25 KB（原完整预估约 350 KB）。本地完整核算从约 2.3 秒降至约 60 毫秒，UTC 核算不再创建时区格式器。这是本地样本，不代表线上延迟保证。浏览器检查使用真实 Web Worker，验证逐个结果、店铺时间展示、搜索、刷新、失败隔离及服务器结账。

Web 其他费用预览及规则日历同样迁到浏览器，接口、兼容范围与安全边界见[Web 计费计算与只读输入](browser-billing-previews.md)。历史营业记录直接读取保存的金额，不重新运行计费规则。
