# Dashboard 账单封顶可解释性设计

## 目标

现场运营页应让员工在不离开玩家账单的情况下核对：每条计时实际覆盖了哪些计费方案和时段、方案内封顶是否已达到，以及多个方案共同参与的全局封顶如何决定当前应付金额。资产与礼物的兑换码列表中，每个兑换码也必须可直接复制。

本设计只改变员工读模型与 Dashboard 展示，不改变现有结算顺序：方案内封顶先作用于按时计费方案，全局封顶随后在参与方案的汇总金额上生效，资产抵扣和员工改单仍在全局封顶之后执行。

## 账单结构

现场账单的主表保持 session 级摘要。一行只显示计时项、开始时间、计费时长、方案小计、状态和停止操作；不再把多个方案或时段塞进该行。

每个 session 可手动展开。展开状态以 session ID 保存于页面状态，在现场数据刷新、价格重新计算和玩家切换时保持不变；仅员工手动折叠才收起。展开内容按发生顺序完整列出所有时段，不省略长时间场次中的日期或时段。

每个时段使用完全相同的布局：

1. `方案名称 · 规则名称`
2. `实际计费：YYYY-MM-DD HH:mm 至 YYYY-MM-DD HH:mm · 时长`
3. `规则时段：HH:mm 至 HH:mm`，跨日规则写为 `HH:mm 至 次日 HH:mm`
4. 右侧固定显示 `本段费用 ¥金额`

若该时段达到方案内封顶，则在同一时段行内显示 `区间内封顶 ¥金额 · 已达到`。它是该时段的计价结果，不另起费用项，也不使用折扣或减免措辞。未达到方案内封顶的时段不显示封顶徽标。

## 全局封顶窗口

全局封顶位于所有 session 的外层，不能归属到任意单一 session。按 `capConfigId`、`capRuleId` 和封顶规则锚定时间分组；每个分组是一个独立的封顶窗口。例如夜间窗口显示为：

`2026-07-09 夜间`  
`2026-07-09 22:00 至 2026-07-10 10:00`

窗口摘要始终显示规则名称、实际窗口范围及结果。展开后显示参与本窗口的 session，以及“参与金额 -> 封顶金额”或“参与金额 -> 当前计入金额”。全局封顶必须使用“封顶至 ¥金额”这一语义，不能把内部差额作为 `-¥金额` 的折扣行展示。

同一个玩家跨多日未结账时，每个日间或夜间窗口独立列出，不能合并为一条“日夜封顶”。窗口数量可以任意增长，页面允许自然滚动；不截断、不省略，也不把多日窗口压成汇总数字。

若同一个封顶窗口已有历史已结算金额，窗口明细还需明确区分历史已计入、本次参与金额和本次按剩余封顶可计入的金额，确保员工能解释剩余额度而非误以为当前 session 独占整个上限。

## 员工读模型契约

`GET /rpc/staff/live-players` 扩展为能渲染上述信息的稳定读模型。保留现有 `pricingCharges` 以兼容现有消费者，同时新增结构化字段：

- 每个 session 的 `pricingSegments`：方案 ID 与名称、规则 ID 与名称、实际起止时间、规则时段、最终本段费用，以及可选的方案内封顶状态与金额。
- 每个 player 的 `globalCapWindows`：封顶配置与规则标识及名称、窗口实际起止时间、参与 session 和方案、历史已计入金额、本次参与金额、封顶金额、当前窗口本次计入金额和是否已达到封顶。

服务端从结算预览的原始费用项和封顶计算过程派生这些字段；Dashboard 不重新按时间猜测区间、不自行分摊封顶，也不由金额差倒推封顶状态。跨多个 session 命中同一全局窗口时，服务端以计费期间的实际贡献产生可审计归属，所有归属金额相加必须精确等于该窗口本次计入金额。

为支持未达到封顶但仍需展示的窗口，按时计费和全局封顶计算需要提供解释性结果，而不只是在触发差额调整时输出 adjustment。结算持久化仍沿用既有 `pricing_cap_history_entries` 语义；新增字段仅是预览读模型。

## 兑换码复制

资产与礼物的兑换码页中，每条兑换码右侧提供带 tooltip 的复制图标。点击后把完整兑换码写入系统剪贴板，并显示短暂的“兑换码已复制”反馈。复制不会改变兑换码状态，也不调用后端写接口。

## 错误和空状态

读模型缺失新增字段时，Dashboard 必须仍可展示现有 session 摘要和 `pricingCharges`，并在详情区域提示计费明细暂不可用；不能以不完整字段推导封顶。没有全局封顶窗口时不渲染全局封顶区块。没有达到方案内封顶时不显示封顶状态。

## 测试

- 核心/应用层测试覆盖单日、跨午夜、跨多日、多 session 共用窗口、已有封顶历史和未达到封顶的解释性结果；验证窗口金额和 session 归属金额守恒。
- Hono 路由测试验证 `live-players` 返回结构化时段和全局封顶窗口，且保留既有 `pricingCharges`。
- Flutter 模型和 widget 测试验证完整时间范围、方案内封顶内嵌展示、所有全局窗口、展开状态在刷新后保留、以及兑换码复制反馈。
- 更新 `docs/api.md` 和 `docs/architecture.md`，说明新增员工读模型字段、两级封顶展示规则及复制行为。
